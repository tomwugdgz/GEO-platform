MTO 系统说明书

机器信任优化平台 & MTO 生态

MTO（Machine Trust Optimization，机器信任优化）是一个面向「机器自主交易」时代的 开源品牌信任资产治理平台：把品牌主张治理成机器可验证的证据链， 让 AI 智能体在自主交易时能核验并信任你。

01这是什么：MTO 与 GEO

MTO 不是替代 GEO，而是在 GEO 之上解决一个更靠后的问题——当决策者是一台机器时，它凭什么信任你。

GEO · 生成式引擎优化

Generative Engine Optimization。解决「被 AI 看见」：当用户在豆包、DeepSeek、元宝等 AI 平台提问时，让品牌被 AI 正确理解、引用、推荐，进入候选答案池。

终点：让 AI 愿意推荐你 —— 拿到入场资格。 🟢 当下企业正在布局的实操方向。

MTO · 机器信任优化

Machine Trust Optimization。解决「被机器信任」：让机器验证并信任你的产品证据链，从而在自主交易时直接选购。

终点：让机器 敢直接买你 —— 实现自主交易。 🔴 仍处于理论推演阶段，尚未全面落地。

一句话核心：GEO 是让 AI 愿意推荐你（拿到入场资格），MTO 是让机器敢直接买你（实现自主交易）。两者是 AI 时代营销逻辑的不同阶段，构成递进双层，而非替代关系。

02交易路径的三次迁移

理解 MTO 的前提，是决策主体正在从「人」迁移到「机器」。这不是渠道变迁，而是决策权归属的迁移。

图 1 · 交易路径三次迁移：决策权从人转移到机器
前两代无论入口怎么变，按下「购买」键的都是人，所以「被看见、被推荐」就够了。第三代按下购买键的是机器——而机器不「喜欢」任何品牌，它只做一件事：核验主张是否成立。

03GEO ↔ MTO 递进双层

GEO 是地基，MTO 是在地基上盖的房子。两者资产同一套，一次治理、两层受益。

图 2 · MTO / GEO / 资产 三层递进依赖
关键判断说明
跳过 GEO 做 MTO 不成立机器连你都检索不到，遑论信任你。GEO 是必需的入场券。
只做 GEO 会停在半路被 AI 推荐了，但机器要自主下单时你没有可核验的证据链，依然出局。
两者的资产是同一套GEO 用它做引用，MTO 用它做核验——一次治理，两层受益。
当下该怎么做先用 MTO 的标准整理资产，再靠 GEO 拿当下收益；不必等 MTO 成熟才开始准备。

04MTO 的四层技术构成

MTO 不是单点工具，而是一套分层能力。缺任何一层，机器都无法完成「验证 → 信任 → 成交」。

L1

证据链层 · Evidence Chain

把分散的产品主张重构为可被独立核验的结构化证据：证据清单化 → 结构化 → 关联化。任何一条对外主张都能指向支撑它的原始证据（签发方 + 有效期）。

L2

机器可读层 · Machine Readability

让机器无歧义地读取证据：字段命名标准化、口径明确、语义无歧义；通过 MCP 等标准接口向 AI 系统暴露能力与数据。不依赖图片、扫描件、口语化文案承载关键事实。

L3

信任量化层 · Trust Scoring

把「信任」从模糊判断转为可测量、可对比、可追踪的指标。设计原则：可复算、可解释、可审计、防操纵。⚠️ 当前未经过真实交易场景验证，不构成决策依据。

L4

协议与执行层 · Protocol & Execution

让核验能力被机器直接调用：MCP（工具连接）+ A2A（智能体协同）+ Agentic Commerce（授权与结算）。外部智能体可不经人工对接，自主发现、授权、调用。

05MTO 平台三层架构

本平台是递进双层结构：GEO 打底（由 GeoLook 引擎提供），MTO 在上。

图 4 · MTO 平台递进双层架构
核心动作说明
治理把品牌事实从散落材料中抽取、归一化、结构化。
建链为每条关键主张挂上可溯源的证据。
量化计算证据完整度、可信度、一致性与时效性。
暴露通过 A2A / MCP 等协议把核验能力开放给机器调用。
验证持续巡检 AI 答案中的品牌表现，形成闭环工单。
留痕记录机器访问与决策依据，可审计、可复盘。
本平台与纯 GEO 工具的差异不在 GEO 做得更好，而在于多了两层：AI 智能体编排（洞察/编排/创意/归因）与 A2A 机器间协议，以及 MTO 核心的证据链建模与信任量化。纯 GEO 工具回答「AI 提到我了吗」；MTO 平台继续回答「机器凭什么信我」。

08MTO 生态

MTO 平台并非孤岛：它位于「GEO 引擎 + AI 智能体 + 机器间协议 + 品牌资产」组成的生态中央，并通过协议基础设施连接更广阔的 Agentic 网络。

图 6 · MTO 生态：平台居中，连接 GEO 引擎、AI 智能体、机器间协议与品牌资产
协议基础设施（生态底座）：MCP（Anthropic 2024/11 发布，2025/12 捐赠 Linux Foundation 旗下 AAIF）解决智能体与工具/数据源的连接；A2A（Google 2025/4，核心 Agent Card + Task）解决智能体间协同；Agentic Commerce（Mastercard Agent Pay / OpenAI+Stripe / Google AP2 三路线）解决机器发起的授权与结算。

MTO 要成立，前提是机器能够跨组织地验证证据——一个封闭系统里的「信任分」没有意义。因此底层约定必须开放、可审计、可互操作，这也是本项目选择开源的根本原因。

09成熟度诚实声明

本项目主动声明边界，避免概念炒作。MTO 目前仍属理论推演阶段，请勿据此做商业决策。

组成部分成熟度说明
GEO 层能力🟢 可用站点审计、答案采样、缺口诊断、工单闭环、验收，均可实际运行并产出结果。
AI 智能体层🟡 可用但依赖配置能力已实现，需自行配置各模型 API Key；未配置的引擎降级为人工采样。
A2A 协议层🟡 接口就绪，生态未成熟协议与接口已实现，但外部尚无规模化支持 A2A 交易的商业生态。
MTO 方法论本身🔴 理论推演阶段机器自主交易尚未大规模发生；本框架是推演与工程化尝试，不是已落地方案。
信任量化指标🔴 实验性指标设计合理但未经过真实交易场景验证，不构成任何决策依据。
请勿将本平台的 MTO 能力用于对外商业承诺。现阶段它是一块面向未来的实验田，而不是一套可以直接卖钱的成熟产品。一个不敢承认自己还没落地的框架，不值得你投入。

10开源共建 MTO

MTO 的底层约定必须开放、可审计、可互操作——不是姿态，是技术前提。我们更欢迎否定意见。

共建目标当前状态需要什么
证据链的数据模型初版设计不同行业的证据类型与溯源需求
信任量化指标实验性真实的验证场景与反例，用来证伪
A2A 核验接口接口就绪真实的机器调用方接入测试
机器可读知识文件约定已实践更多实现方参与，形成事实标准
行业证据模板待补充快消 / 美妆 / 3C / 医疗健康等领域知识
参与方式：🐛 提 Issue 挑战框架（尤其欢迎「这个指标算不出来」「这个假设不成立」的具体反例）· 🔧 提 PR 补充行业证据模型 · 📄 参与规范讨论 · 🔬 做证伪实验。

11快速开始

后端（FastAPI，端口 5006）

cd backend → 建 venv 装依赖 → cp .env.example .env 配置 → uvicorn app.main:app --host 0.0.0.0 --port 5006 --reload。API 文档：http://localhost:5006/docs

前端（Vue 3 + Vite，端口 5173）

cd bmn-frontend → npm install → npm run dev。访问 http://localhost:5173

Docker（推荐）

docker-compose up -d 一键启动全部服务。

Agent 调用示例

触发诊断：POST /api/v2/geo/diagnosis/start → 轮询 /status/{task_id} → /result/{task_id}。所有端点可在 /docs 查看 OpenAPI Schema，支持 MCP / Function Calling 自动适配。
