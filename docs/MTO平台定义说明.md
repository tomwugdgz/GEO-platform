## 一、一句话定义

**MTO（Machine Trust Optimization，机器信任优化）** 是一套面向「机器自主交易」时代的方法与工具集：
它把品牌的产品主张从**人类可读的营销文案**，重构为**机器可验证的证据链**，
使 AI 智能体在自主完成购物决策时，能够检索到你、核验你的主张、并**信任你而直接下单**。

**MTO 平台**是这套方法的开源实现：一个把 GEO 可见性能力、AI 智能体编排、A2A 机器间协议
整合在一起的品牌信任资产治理平台。

## 二、术语澄清：GEO 与 MTO

这两个缩写极易混淆，且都在「AI 时代的营销」语境下出现，因此必须先划清边界。

| | **GEO** | **MTO** |
|---|---|---|
| 全称 | Generative Engine Optimization | Machine Trust Optimization |
| 中文 | 生成式引擎优化 | 机器信任优化 |
| 解决的问题 | **被 AI 看见** | **被机器信任** |
| 作用对象 | 生成式 AI 的问答引擎（豆包、DeepSeek 等） | 自主决策的 AI 智能体（Agent） |
| 交付物 | 品牌被 AI 正确理解、引用、推荐 | 品牌证据链被机器验证并采信 |
| 终点 | 进入 AI 的**候选答案池** | 进入机器的**成交决策集** |
| 一句话 | 让 AI **愿意推荐**你 | 让机器**敢直接买**你 |
| 类比 | 拿到**入场资格** | 实现**自主交易** |
| 成熟度 | **已是当下企业正在布局的实操方向** | **仍处于理论推演阶段，尚未全面落地** |

> ⚠️ **重要澄清**：营销领域的 MTO 目前仍处于**理论推演阶段**，尚未全面落地。
> 本平台对其的定义、框架与技术构成，是对未来形态的**推演与工程化尝试**，
> 不代表该形态已在市场上成熟运行。而 GEO 则已经是当下真实存在、企业正在投入的实操方向。
> 本平台同时实现两者：GEO 部分**可用**，MTO 部分**可探讨、可共建**。

## 三、为什么会有 MTO：交易路径的变迁

要理解 MTO，必须先看一次正在发生的路径迁移。

### 3.1 三代交易路径

```
【第一代 · 人找货】搜索 / 电商
  人 → 搜索引擎/货架 → 自己比较 → 自己下单
  优化对象：SEO / 关键词 / 详情页
  竞争焦点：排名

【第二代 · 人问 AI，AI 建议，人下单】
  人 → 问 AI「XX 哪个好」 → AI 给答案 → 人自己去买
  优化对象：GEO
  竞争焦点：被 AI 引用与推荐

【第三代 · 人给目标，机器自主完成】
  人 → 对智能体说「帮我买一瓶适合敏感肌的防晒」 → 智能体自主检索、核验、比价、下单
  优化对象：MTO
  竞争焦点：被机器信任
```

### 3.2 关键变化是什么

第一代到第二代，变的是**人获取信息的入口**：从搜索引擎变成 AI 问答。
第二代到第三代，变的是**决策权本身**：从人转移到了机器。

这是本质区别——

- 前两代，无论入口怎么变，**最终按下"购买"键的仍然是人**。
  营销的目标是影响人的判断，所以「被看见、被推荐、被喜欢」就够了。
- 第三代，**按下"购买"键的是机器**。
  机器不"喜欢"任何品牌，它只做一件事：**核验主张是否成立**。

于是营销的核心命题从「如何让 AI 提到我」变成了
**「如何让机器验证并信任我的产品证据链」**。

这就是 MTO。

### 3.3 一个具体场景

```
用户对智能体说：「我皮肤敏感，帮我买支防晒，预算 200 以内。」

智能体的实际动作（MTO 要服务的全过程）：
  ① 检索      → 从可访问的商品/品牌数据源中找到候选
  ② 核验      → 逐条验证主张：「敏感肌适用」有依据吗？成分表在哪？
                 「SPF50」是谁测的？检测报告可溯源吗？有没有第三方背书？
  ③ 比对      → 在通过核验的候选里比价、比成分、比评价可信度
  ④ 决策      → 选出它认为「风险最低」的那一个
  ⑤ 成交      → 通过 A2A / 支付协议直接下单

在这条链路里，GEO 能做的只有 ①（被检索到）。
②③④⑤ 全部属于 MTO 的范畴。
而绝大多数品牌目前连 ① 之后发生了什么都不知道。
```

## 四、GEO vs MTO：递进双层架构

两者不是替代关系，而是**递进关系**。GEO 是地基，MTO 是在地基上盖的房子。

```
                ┌─────────────────────────────────────────────┐
   MTO 层       │   被机器信任                                 │
   （上层）      │   证据链可核验 · 信任可量化 · 可被 A2A 调用      │
                │   目标：机器自主交易时选择你                     │
                └────────────────────┬────────────────────────┘
                                     │  依赖 ↓ 建立在
                ┌────────────────────┴────────────────────────┐
   GEO 层       │   被 AI 看见                                 │
   （打底层）    │   被正确理解 · 被引用 · 被推荐                  │
                │   目标：进入 AI 的候选答案池                    │
                └────────────────────┬────────────────────────┘
                                     │  依赖 ↓ 建立在
                ┌────────────────────┴────────────────────────┐
   资产层       │   品牌知识资产                                │
                │   品牌事实 · 产品事实 · 结构化数据 · 内容资产     │
                └─────────────────────────────────────────────┘
```

### 关键判断

| 判断 | 说明 |
|---|---|
| **跳过 GEO 做 MTO 不成立** | 机器连你都检索不到，遑论信任你。GEO 是必需的入场券 |
| **只做 GEO 会停在半路** | 被 AI 推荐了，但机器要自主下单时你没有可核验的证据链，依然出局 |
| **两者的资产是同一套** | 品牌事实、产品事实、结构化内容——GEO 用它做引用，MTO 用它做核验。**一次治理，两层受益** |
| **当前投入顺序** | 现阶段应**先做扎实的 GEO**（可立刻见效），同时**按 MTO 的口径组织资产**（为未来埋伏笔） |

> 最后一条是本平台的核心主张：
> **不要等 MTO 成熟了再准备。MTO 需要的证据链，正是 GEO 需要的高质量结构化资产。**
> 现在按 MTO 的标准整理，GEO 阶段就能拿到收益。

## 五、MTO 的四层技术构成

MTO 不是一个词，而是四层能力的叠加。缺少任何一层，机器都无法完成「验证 → 信任 → 成交」。

### 第一层 · 证据链（Evidence Chain）

**机器不信任主张，只信任证据。** 品牌说「敏感肌适用」没有意义，
有意义的是这个主张能沿着一条可追溯的链路走到原始凭据。

```
主张：「适合敏感肌」
  ├─ 成分依据   → 全成分表（结构化、可解析）
  ├─ 测试依据   → 第三方检测报告（可溯源、有出具方与日期）
  ├─ 认证依据   → 认证机构、证书编号、有效期
  ├─ 临床依据   → 试验数据、样本量、结论
  └─ 反馈依据   → 真实评价的可信度信号（非刷单）
```

**要点**：证据必须**结构化**（不是图片里的文字）、**可溯源**（能追到出具方）、**可核验**（第三方能独立确认）。

### 第二层 · 机器可读性（Machine Readability）

证据存在不等于机器能读到。这一层解决「可访问、可解析、可理解」：

- 结构化数据（JSON-LD / Schema.org 及行业扩展）
- 机器可读的产品/品牌知识文件（如 `llms.txt` 一类约定）
- 稳定的数据接口，而非只有人类可读的页面
- 明确的数据许可与调用边界（机器需要知道「我能不能用」）

### 第三层 · 信任量化（Trust Quantification）

机器需要一个**可比较的量**。这一层把无形的「信任」变成可计算、可解释的指标：

| 维度 | 机器关心的问题 |
|---|---|
| 证据完整度 | 关键主张有多少条带证据？ |
| 证据可信度 | 证据来自谁？是否第三方？是否过期？ |
| 主张一致性 | 官网、电商页、检测报告之间是否自相矛盾？ |
| 可验证性 | 机器能否独立复现验证过程？ |
| 时效性 | 证据是否仍有效？多久前更新？ |

**这一层是 MTO 与 GEO 最大的分野**：GEO 关心「AI 有没有提到我」，
MTO 关心「AI 能不能证明我说的是真的」。

### 第四层 · 协议与执行（A2A & Execution）

前三层让机器**愿意**信任你，第四层让机器**能够**与你完成交易：

- **A2A（Agent-to-Agent）**：机器与机器之间发现、协商、调用的协议层
- **机器身份与授权**：确认调用方是谁、被授权做什么
- **标准化交易接口**：报价、库存、履约、售后，全部机器可调用
- **可审计日志**：每一次机器决策留痕，可回溯「它为什么选了你」

> 这是 MTO 的终点：**从「被推荐」走到「被交易」**。

## 六、MTO 平台的定义

### 6.1 平台定位

> **MTO 平台是一个开源的品牌信任资产治理平台。**
> 它把品牌的散落事实，治理成「人类可读、AI 可引用、机器可核验」的信任资产，
> 并通过 AI 智能体与 A2A 协议，让这些资产在机器自主决策的场景中被检索、核验与采信。

### 6.2 三层架构

```
┌──────────────────────────────────────────────────────────────┐
│  MTO 层 · 机器信任                                             │
│  · 证据链建模与治理      · 信任量化评分                          │
│  · A2A 能力暴露与协议对接  · 机器调用审计日志                      │
├──────────────────────────────────────────────────────────────┤
│  GEO 层 · AI 可见性  ← 由 GeoLook 引擎提供                      │
│  · 站点状态审计  · AI 答案采样  · 缺口诊断                        │
│  · 工单生成与闭环验收  · 渠道/竞品分析                            │
├──────────────────────────────────────────────────────────────┤
│  资产层 · 品牌知识底座                                          │
│  · 品牌事实库   · 产品事实库   · 结构化内容资产   · 知识库检索      │
└──────────────────────────────────────────────────────────────┘
```

### 6.3 平台的核心动作

| 动作 | 说明 |
|---|---|
| **治理** | 把品牌事实从散落材料中抽取、归一化、结构化 |
| **建链** | 为每条关键主张挂上可溯源的证据 |
| **量化** | 计算证据完整度、可信度、一致性与时效性 |
| **暴露** | 通过 A2A / MCP 等协议把核验能力开放给机器调用 |
| **验证** | 持续巡检 AI 答案中的品牌表现，形成闭环工单 |
| **留痕** | 记录机器访问与决策依据，可审计、可复盘 |

## 七、本平台与纯 GEO 工具的差异

市面上已有成熟的 GEO 工具。本平台的差异**不在 GEO 做得更好，而在于多了两层**：

| 能力 | 纯 GEO 工具 | **MTO 平台** |
|---|---|---|
| AI 可见性诊断（站点审计 / 采样 / 缺口） | ✅ | ✅ **（内置，由 GeoLook 引擎提供）** |
| 工单化闭环与验收 | ✅ | ✅ |
| **AI 智能体编排** | ❌ | ✅ **多智能体协同：洞察 / 编排 / 创意 / 归因** |
| **A2A 机器间协议** | ❌ | ✅ **把品牌核验能力暴露为机器可调用能力** |
| **证据链建模与信任量化** | ❌ | ✅ **MTO 核心：从"被提到"到"被证明"** |
| **机器调用审计** | ❌ | ✅ 记录机器为何选择你 |

**一句话概括差异**：

> 纯 GEO 工具回答「AI 提到我了吗」；
> **MTO 平台在回答这个之后，继续回答「机器凭什么信我」。**

## 八、成熟度诚实声明

**本项目主动声明边界，避免概念炒作。**

| 部分 | 成熟度 | 说明 |

## 九、开源共建 MTO

### 为什么必须开源

MTO 要成立，前提是**机器能够跨组织地验证证据**。
一个封闭系统里的「信任分」没有意义——机器凭什么相信一个它无法审计的黑盒？

因此 MTO 的底层约定必须是**开放、可审计、可互操作**的。
这也是本项目选择开源的根本原因：**不是姿态，是技术前提。**

### 我们在共建什么

| 共建目标 | 当前状态 | 需要什么 |
|---|---|---|
| **证据链的数据模型** | 初版设计 | 来自不同行业的证据类型与溯源需求 |
| **信任量化指标** | 实验性 | 真实的验证场景与反例，用来证伪 |
| **A2A 核验接口** | 接口就绪 | 真实的机器调用方接入测试 |
| **机器可读知识文件约定** | 已实践 | 更多实现方参与，形成事实标准 |
| **行业证据模板** | 待补充 | 快消 / 美妆 / 3C / 医疗健康等行业的领域知识 |

### 如何参与

- 🐛 **提 Issue 挑战我们的框架** —— 尤其欢迎「这个指标算不出来」或「这个假设不成立」的具体反例
- 🔧 **提 PR 补充行业证据模型** —— 你所在行业的一条真实证据链，比十页理论更有价值
- 📄 **参与规范讨论** —— 证据链格式、信任指标口径、A2A 接口约定
- 🔬 **做证伪实验** —— 试着用我们的方法让一个机器完成真实核验，然后把失败的地方告诉我们

> **我们更欢迎否定意见。** 一个仍在理论推演阶段的框架，
> 最大的风险不是被批评，而是被附和。

## 十一、常见问题

**Q1：MTO 和 GEO 我该先做哪个？**
先做 GEO。GEO 是当下可实操、能立刻见效的方向，而且它需要的资产（品牌事实、结构化内容、机器可读文件）正是 MTO 的输入。**用 MTO 的标准组织资产，用 GEO 的方式拿当下收益。**

**Q2：MTO 现在有用吗？**
作为**方法论和资产整理标准**，现在就有用；作为**已落地的商业方案**，还不是。
本平台的价值在于：让你在机器自主交易真正普及时，资产已经就位。

**Q3：为什么机器不能直接信任品牌官网的宣传？**
因为宣传是**主张**不是**证据**。机器需要的是能独立复现的验证过程——谁测的、怎么测的、数据在哪、能否溯源。官网文案无法满足这个要求，结构化且可溯源的证据链可以。

**Q4：MTO 会不会又是一轮概念炒作？**
有这个风险，所以我们把成熟度分级写进了文档（见第八节），并把「MTO 仍属理论推演阶段」放在最显眼的位置。**一个不敢承认自己还没落地的框架，不值得你投入。**

**Q5：平台和 GeoLook 是什么关系？**
本平台的 **GEO 引擎内核来自开源项目 [GeoLook](https://github.com/aigclink/geolook)**（MIT 许可），版权归其作者所有。MTO 平台在其之上补充了资产治理、AI 智能体编排与 A2A 信任层。详见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 与 [README 致谢](../README.md#-致谢)。

**Q6：这个项目能商用吗？**
本项目自身是**个人非商业性质的开源项目**，请见[版权与使用声明](../README.md#️-版权与使用声明)。上游 GeoLook 采用 MIT 协议，可自由使用。
